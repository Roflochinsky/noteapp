# Цикл эпика

Не конвейер фаз, а **петля**. Одна итерация = один срез, и она самодостаточна: всё нужное
читается из `bd` и файла плана, а не из контекста разговора, поэтому её можно повторять в
свежей сессии, после компактификации и вообще в новом процессе. **Состояние живёт снаружи
головы** — не помнить, а перечитывать: `bd show <эпик>` (описание, пути спеки и плана),
`scripts/ready-slices.py <эпик>` (что брать), файл плана (шаги, попытки, вердикты, ретро).

Wayfinder-карта и эпик не конкурируют: карта решает «что строим» (пункт назначения — спека),
эпик исполняет уже решённое. Спека из карты — вход режима 1. Форма 2 харнеса перенесена из
workwatch 2026-09-05 (bd nikitatrubaev-ei5); пилот на воркерах Orca — скилл `epic-orca`.

## Шаг 0. Определи режим

По `bd show <эпик>` и `bd ready --parent <эпик>`: эпика нет → **режим 1**; есть открытые дети
→ **режим 2**; детей нет, эпик открыт → **режим 3**; эпик закрыт → напечатать «эпик закрыт,
работы нет» и **завершиться**. Последнее — терминальное состояние: без него внешний `while`
будет вечно перезакрывать закрытый эпик.

## Режим 1. Подготовка (эпика ещё нет) — только с человеком

1. `discuss` (внутри зовёт `grilling`, ведёт протокол в `docs/discussions/`) — снять неясности.
   **Непропускаем: «запрос и так ясен» — не причина** (workwatch 2026-08-19: «ясный» запрос
   дал 12 решений, три из них новые требования). Пропуск — только если владелец сам сказал
   «без интервью»; уже отвеченные им развилки (в разговоре, в wayfinder-карте) не
   переспрашивать. Новый экран или крупный UI: сначала `impeccable:impeccable` в главной
   сессии — направление и комп фиксируются в `docs/design/` и разделом спеки.
2. Спека — скиллом `to-spec` в `docs/specs/<дата>-<слаг>.md`, две части, `spec-check` зелёный.
   Сработал ADR-гейт — скилл `adr`, файл в `docs/adr/`, подпись владельца; это единственное
   место, где нужна подпись. Затронуто 2+ слоя — в спеке обязателен раздел «Архитектура (HLD)».
3. План в `docs/plans/` с тем же слагом. План — это LLD; отдельных HLD/LLD-доков не заводим.
   Для задач с тестами план фиксирует **seams**. Журналы срезов живут рядом:
   `docs/plans/<слаг>/<id>.md` — план перестаёт быть общим файлом исполнителей.
4. bd-эпик и дети-срезы — скиллом `to-tickets`: каждый демонстрируем сам по себе, у каждого
   строка «Трогает:», срезы не делят файлы; широкие рефакторы и смены формата — expand–contract.
5. Пути спеки и плана записать в описание эпика — из него их берут все следующие итерации.
6. **ОСТАНОВКА на апрув.** Показать владельцу пачкой, языком `wait-what`: человеческую часть
   спеки, ADR (`Proposed`), список срезов — что он увидит работающим после каждого, открытые
   развилки. Код и внутренние решения не показывать. Дальше не идти, пока не апрувил.

## Ревью замысла — один раз, между режимами 1 и 2

До первой строки кода, иначе правится уже написанное. Оси — **параллельные `na-reviewer` на
`fable`**, роутинг по типу работы, вердикты в план, находки правятся ДО первой итерации. Шаги,
рубрики, права осей и форма отчёта — скилл **`review-intent`** и `docs/harness/epic.md`.

## Режим 2. Итерация (у эпика есть открытые дети)

Разрешения внутри эпика не спрашивают, порядок шагов не меняют.

1. **Набор срезов на круг выдаёт `scripts/ready-slices.py <эпик> -n 3`** — он берёт
   `bd ready --parent`, применяет пересечение по строкам «Трогает:», замки общих ресурсов и
   рёбра `bd`, и печатает непересекающийся набор с причиной для каждого отвергнутого. Каждому
   выданному — `bd update <id> --claim`. **Каждый исполнитель — в своём дереве**
   (`isolation: "worktree"`): в общем дереве одновременно пишет ровно один.

   **Потолок пишущих — два, и это память, а не правило.** Машина 16 ядер / 11 ГБ, один прогон
   гейта — Gradle-демон 2 ГБ плюс Kotlin-демон 1,5 ГБ; `bin/gate` ставит прогоны в очередь
   через `flock`, ждущий прогон убивать не надо. Прежде чем считать агента повисшим —
   `ps -eo pid,etime,cmd | grep gradle`: идущий `GradleWrapperMain` работает, а не умер.
   Агент, который НЕ собирает, стоит ~0,5 ГБ — таких можно держать сколько угодно.

   **База дерева — локальная ветка `main`.** Первым делом в дереве:
   `git rev-list --left-right --count main...HEAD` — не ноль слева, дерево отстало
   (workwatch: дерево на 777 коммитов позади сдало зелёные гейты на коде полугодовой давности).
   **После любого вызова `bd` рабочий каталог сбрасывается в корень основного дерева** —
   каждая `git`-команда в дереве агента идёт с `git -C <путь-дерева>` (2026-08-30: журнал
   среза уехал коммитом в `main`). В свежем дереве нет `local.properties` — `bin/gate`
   копирует его сам.
2. Строка в чат: какой срез взят и что в нём должно заработать, дальше — строка на каждый
   диспатч. Что обязано стоять в промпте — из наступленного:
   * **Замеры несут потолок** по времени или числу прогонов, отчёт из намеренного пишется ДО
     последних проверок с пометкой «не домерено».
   * **Цифр «сейчас столько-то» в промпт не писать** (2026-08-30: «на main 116 тестов» из
     неслитой ветки, на main их было 66) — базовую цифру исполнитель меряет сам.
   * **Скратчпад у агентов ОБЩИЙ — черновики именуй `<id-среза>-<имя>`.**
   * **У каждого среза есть право СМОНТИРОВАТЬ своё** — строка в `AndroidManifest.xml`,
     вкладка в `MainActivity`, задача в `build.gradle.kts`; блок, который негде подключить,
     не сдан; конфликт двух срезов в этих строках разрешается порядком из спеки.
   * **Утверждение из отчёта агента — не факт, пока ведущий его не проверил**, и переносить
     его в промпт следующему опаснее всего: промпт — инструкция, а не пересказ.
   * **Примеры входа → выхода** из критериев спеки и слов владельца — в промпт исполнителя те
     же, что получит ревьюер (workwatch: три из четырёх находок класса `a` ловились бы ими).
3. **Исполнитель — сабагент `na-executor`** (`opus`, medium; класс «тихая и дорогая ошибка» —
   очередь, идемпотентность пуша, `ConflictRule`, frontmatter, клиент GitHub, миграция, всё
   под ADR-гейтом — high). Пути в промпте (спека, план, `bd show <id>`), не пересказ разговора;
   мандат `tdd` и четыре правила границ правки — из определения агента. UI-срезы: плюс
   утверждённый комп и `DESIGN.md` как жёсткое ограничение. Сдаёт по форме агента: изменённые
   файлы против «Трогает:», `гейты: <sha>` с выводом файлом, таблицу мутаций, риски, откат.
   **Диспатчил своих — закрыл их до сдачи**; глубина сабагентов в проекте 1
   (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`), внуков не бывает.

   **Отчёт пришёл — агент гасится в том же ответе** (`TaskStop`), до разбора находок: живой
   агент шлёт повторные idle-уведомления и засоряет ленту владельцу. Нужен тот же контекст ещё
   раз — `SendMessage` ДО того, как погасил. Скиллы плодят своих сабагентов — гасить их только
   вместе с родителем (2026-08-29: погашенные оси стали недостижимы, ревьюер переделывал сам).
4. Верификация: исполнитель гонит `bin/gate` (UI/APK — `bin/gate --full`), реальный вывод;
   красное — чинить, а не отчитываться. **Каждую неудачную попытку записать в журнал среза
   строкой «попытка N по срезу <id>: что красное»** — счётчик обязан жить снаружи головы.
5. **Ревью — отдельный агент `na-reviewer`, автор себя не одобряет.** Форму выбирай по цене
   ошибки: «тихая и дорогая» (см. шаг 3) — **две оси ОТДЕЛЬНЫМИ агентами, диспатчит ведущий**;
   косметика и экраны без логики — один ревьюер проходит обе оси внутри себя. Гейты ревьюер
   ПРИНИМАЕТ по sha из отчёта, когда файл вывода есть и hash равен HEAD. Вердикт по форме семи
   пунктов `docs/harness/epic.md`, все находки, классы предлагает ревьюер — утверждает ведущий.
   **Молчание об оси = ось не пройдена**, сведение вердиктов — работа ведущего.

   **Мутация главной правки — обязательна:** `scripts/mutate.py run --id <id> --spec
   <файл.toml>` на сданном HEAD, таблица — `scripts/mutate.py table`. Скрипт держит сам: отказ
   на грязном и чужом дереве, уникальность ключа, sha в четырёх точках, откат копией, ровно
   `1 failed` с именем теста, управляющую мутацию, отказ на задаче из кэша. Человеку — выбор
   разделяющего случая и грабли Gradle из `docs/harness/epic.md`.
6. **Круг фикса — по старшему классу находки** (уровни П/У/Г — `docs/harness/epic.md`): `a`
   или больше 20 строк прод-кода — полное второе ревью ТЕМ ЖЕ ревьюером в продолжении
   контекста; `t` стража класса «тихая и дорогая» — узкое подтверждение тем же ревьюером;
   остальное — гейты и убитая мутация, без ревьюера. **Находки без блокера остаются в вердикте
   и задачами не становятся** — задача в `bd` только срез спеки; исключения — класс `a` вне
   среза и вопрос владельцу.
7. Слияние в **локальный `main`** по одному, **после слияния `bin/gate` гоняется заново**:
   зелёное в двух деревьях порознь не означает зелёное вместе. Коммит по-русски со ссылкой на
   id среза; журнал среза сшить в план. Пуш — при закрытии сессии или эпика
   (`CLAUDE.md` → _Session Completion_), не после каждого среза.
8. **Показ поведения — вторая точка касания владельца.** Зелёные юнит-тесты сдачей НЕ
   считаются. Срезы приложения: `bin/gate --full` собрал APK, сквозной смоук против
   **тестового** репо `Roflochinsky/voice-notes-test`; установка на OnePlus 13 и прогон
   руками — владельцу, телефон не стенд. Срезы Action: прогон workflow на тестовом репо,
   ссылка на run. Владельцу одной строкой: что теперь работает и как это увидеть. Только
   после этого `bd close <id>`.
9. **Вернуться к шагу 0 и взять следующий срез сразу:** после апрува режима 1 петля крутится
   сама — не спрашивать «продолжать?», не подводить промежуточные итоги вместо работы.
   Останавливаться только по списку «Когда остановиться» ниже.

2. Дизайн-ось для эпиков с UI (один раз, когда UI собран) — процедура и входной контракт в
   `docs/harness/epic.md`.
3. **Архитектурная проверка эпика — `na-reviewer` с рубрикой
   `mattpocock-skills:codebase-design`, усилие high.** Предмет — дифф всего эпика. Найденное

4. `scripts/epic-metrics.py --session <id> --plan <план>` → таблица в раздел `## Retro` плана;
   пять вопросов ретро (`docs/harness/epic.md`); продуктовые доки при смене поведения

5. `git pull --rebase=merges && git push` (плоский `--rebase` переписывает merge-коммиты срезов
   в цепочку); `bd close <эпик>`; отчёт человеку.

## Чем крутить петлю

**По умолчанию — сам, до конца.** Апрув режима 1 получен → срезы берутся один за другим, пока
не сработает условие остановки или не закроется эпик; спросить «крутить дальше?» — это и есть
невыполнение петли.

- сам в этой сессии — повторяй шаг 0, контекст не растёт, вся работа у сабагентов;
- `/loop /epic nikitatrubaev-xxx` — харнесс вызывает скилл снова;
- снаружи: `while :; do claude -p "/epic nikitatrubaev-xxx"; done`, выход — по терминальному шагу 0.

## Когда остановиться и спросить человека

Останавливаясь: `bd update <id> --status=blocked` и причина в файл плана — заблокированное
`bd ready` не показывает, иначе следующая итерация повторит ту же работу.

- Развилка спеки или сработавший ADR-гейт — это подпись владельца, не решение агента.
- Гейт красный после двух попыток (счёт — по записям в журнале среза, шаг 4).
- Один и тот же вердикт `CHANGES REQUESTED` дважды подряд по одному месту — петля не сходится.
- Работа вышла за границы среза: не расширять срез молча, завести отдельный `bd`-issue.
- **Телефон и живые сервисы.** Всё, что трогает реальный OnePlus 13 (установка APK, смена
  роли ассистента, настройки системы), боевой репо заметок с реальными данными или ключи
  (Deepgram, GitHub token, CLAUDE_CODE_OAUTH_TOKEN) — только по явному указанию владельца.
  Автономия петли сюда не распространяется: срез доводится до края и ждёт.

Во всех остальных случаях не спрашивать: вопрос стоит дороже, чем цена ошибки на срезе.
