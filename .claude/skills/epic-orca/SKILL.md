# Цикл эпика на Orca

Петля, не конвейер: одна итерация = один срез, состояние снаружи головы — `bd`, файл плана,
забег Orca. Два канала запуска агентов: **воркеры Orca** (`worker-start`, свои деревья, только
`--model/--effort`; мандаты — первыми строками файла промпта) для исполнения и ревью кода;
**канал `Agent`** с определениями `.claude/agents/na-*.md` для ревью замысла и исследований.
Вложенность в обоих — глубина 1. Перенесено из workwatch 2026-09-05 (форма 2, спека того репо
`docs/specs/2026-09-02-harness-orca-pipeline.md`); здесь только шаги. Режимы 1 и 3, правила
промпта и «Когда остановиться» — скилл `epic`, ниже только то, что отличается.

**Не домерено для noteapp** (закрывает первый пилот): Orca 1.4.197 на этом репо ни разу не
запускалась; `orca.yaml` (setup копирует `local.properties`, сверяет базу с локальным `main`)
написан по образцу workwatch и не прогнан; пик памяти воркеров рядом с Gradle-демонами не
снят — потолок исполнителей ставить **2**, пока замер не покажет больше.

## Шаг 0. Режим

`bd show <эпик>`, `bd ready --parent <эпик>`: эпика нет → режим 1 (скилл `epic`); открытые
дети → режим 2; детей нет → режим 3 (скилл `epic`, плюс уборка ниже); эпик закрыт — «эпик
закрыт, работы нет», завершиться.

## Режим 2. Итерация

1. **Набор.** `free -m` перед диспатчем: при свободных меньше 1,5 ГБ следующий процесс не
   поднимать, сначала уборка (шаг 5). `scripts/ready-slices.py <эпик> -n 2`; каждому
   выданному — `bd update <id> --claim` (хук `orca-card-sync` двигает карточку Orca).
   **Готово:** список взятых срезов напечатан в чат, по строке на срез.
2. **Забег и задачи.** `orca orchestration run-current`, нет — `run-create --objective "<эпик>"`.
   Промпт исполнителя — файлом `docs/plans/<слаг>/<id>-prompt.md`, писать его инструментом
   Write, не `cat <<EOF` (замер workwatch 2026-09-03: обратные кавычки в heredoc исполняются
   оболочкой и имена файлов исчезают из задания): первые строки — вызов `mattpocock-skills:tdd`
   и четыре правила из `.claude/agents/na-executor.md`; затем пути спеки, плана, `bd show <id>`,
   строка «Трогает:», база дерева `main`, состав сдачи, путь отчёта `docs/plans/<слаг>/<id>.md`.
   Незакоммиченные файлы (промпты, журналы, вердикты) — только АБСОЛЮТНЫМИ путями главного
   дерева: в дереве среза их нет. Полный вывод гейтов — в скратчпад сессии; в журнале —
   строка `гейты: <sha> …` и путь к выводу. Примеры входа → выхода — в промпт исполнителя.
   `task-create --task-title <id> --spec "<путь промпта>"`; зависимости — `--deps`.
   **Готово:** у каждого взятого среза есть задача Orca и файл промпта.
3. **Диспатч.** `worker-start --task <task> --worktree new-child --name <id> --base-branch main
   --agent claude --model opus --effort medium --setup run`; класс «тихая и дорогая» —
   `--effort high`; косметика — `--model sonnet`. На первом диспатче пилота сверить, что
   дерево легло на локальный `main`, а не на `origin/main` (голое имя в Orca — ловушка
   резолва; запасной вариант — `refs/heads/main`), и что setup из `orca.yaml` нашёлся
   (`hookFound: true`, `local.properties` в дереве есть). Строка в чат на каждый диспатч.
   `agent_prompt_blocked` = машина занята: `free -m`, освободить, повторить через 20 с.
   **Готово:** у каждого диспатча `state: ready` и `dispatch_input: accepted`.
4. **Ожидание.** `check --wait --types worker_done,escalation,question --timeout-ms 900000`;
   `question` → `reply` сразу; каждый `worker_done` обработать, затем `check --ack <deliveryId>`
   (без квитанции пачка возвращается из `--wait` мгновенно). Вывод `--wait` — в файл, не в
   `head`. Пятнадцать минут без писем — `worker-list --json`: `process_exited` без письма →
   `task-update --status ready`, новый `worker-start`; процесс жив, но пульсов нет —
   `orca terminal read --screen`: строка «API Error» и пустой промпт = сессия встала; будить
   `orca terminal send --text "Продолжай с места остановки: …" --enter`, не перезапускать.
   Признак простоя — не «процесс жив», а НЕРАСТУЩЕЕ CPU: `awk '{print $14+$15}'
   /proc/<pid>/stat` дважды с паузой. Идущий Gradle (`ps … | grep GradleWrapperMain`) — не простой.
   **Готово:** ни одного диспатча без письма или без записи в `worker-list`.
5. **Приёмка сдачи — до освобождения воркера.** В отчёте есть HEAD, строка гейтов с хешем и
   файл вывода, изменённые файлы против «Трогает:» (расхождение — обязательная находка),
   мутация главной правки (`scripts/mutate.py table`). Чего-то нет — `task-create` на
   доделку и `worker-start --task <доделка> --terminal <handle исполнителя>`.
   **Готово:** все четыре пункта в отчёте; воркер освобождён `worker-release`
   (`retained` → `terminal close --terminal <handle>`, только своих диспатчей; уборка после
   каждого агента обязательна — решение владельца workwatch 7, принято и здесь).
6. **Ревью.** `na-reviewer` воркером в дереве среза (`--worktree branch:<id>`; флаги создания
   для существующего дерева отвергаются): `--model fable --effort medium`; класс «тихая и
   дорогая» — `--effort high` и две оси отдельными воркерами. Форма вердикта —
   `docs/harness/epic.md`, в промпте просить все находки; гейты ревьюер ПРИНИМАЕТ по sha из
   отчёта. **Хвосты в `bd` не заводятся** — остаются в вердикте. **Ревьюера не освобождать до
   конца круга.**
   **Готово:** вердикт с семью пунктами в `docs/plans/<слаг>/<id>-review.md`; классы проставлены.
7. **Круг фикса по старшему классу** (П/У/Г — `docs/harness/epic.md`). `a` → фикс-воркер,
   затем полное второе ревью ТЕМ ЖЕ ревьюером: `task-create` на второе ревью и
   `worker-start --task <review2> --worktree branch:<id> --terminal <handle ревьюера>`. Новый
   ревьюер — только если тот же дважды пропустил `a`. Остальное → фикс, гейты и убитая мутация,
   без ревьюера; исключение — стражи класса «тихая и дорогая»: узкое подтверждение тем же
   ревьюером. Один и тот же вердикт дважды по одному месту — стоп, `bd update
   --status=blocked`, причина в план.
   **Готово:** блокеров нет; все воркеры круга освобождены.
8. **Слияние.** `bd merge-slot acquire` (ошибка → стоп, причина в план) → merge ветки среза в
   локальный `main` → `bin/gate --full` на слитом HEAD → коммит по-русски с id →
   `bd merge-slot release`. Журнал среза сшить в план. Показ поведения и `bd close <id>` — как
   в `epic`, шаг 8. Пуша здесь нет.
   **Готово:** `git log -1` с id среза, гейты зелёные на слитом HEAD, слот `open`.
9. **Уборка среза.** Дочернее дерево среза — `orca worktree rm` (только свои дочерние и только
   после `worker-release`: команда идёт мимо стражей); все воркеры круга освобождены; в
   канале `Agent` — `TaskStop`. Владельцу одной строкой: что слито и что он увидит.
   **Готово:** `worker-list` без диспатчей этого среза, дерева среза нет в `worktree list`.
10. **Шаг 0 снова, сразу.** Очередь пуста, а дети есть — брать следующий срез спеки; хвосты
    ревью срезами не становятся. Ждать владельца только на ADR, телефон и по списку «Когда
    остановиться» скилла `epic`.

## Режим 3. Закрытие — дополнительно к скиллу `epic`

Уборка эпика: `worker-list` пуст, дочерних деревьев эпика нет в `orca worktree list`,
`.mutations/` снят. В ретро — замер пилота: пик памяти при N воркерах рядом с Gradle, число
`agent_prompt_blocked`, доля реально закрытых терминалов `worker-release`.

## Чем крутить

Сам, до конца: после апрува режима 1 срезы берутся без пауз. Снаружи —
`/loop /epic-orca nikitatrubaev-xxx`. Откат формы — скилл `epic` (канал `Agent`).
