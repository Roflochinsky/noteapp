# Спека из разговора

Спека **записывает уже принятые решения** и не порождает новых. Всплыл нерешённый вопрос —
сними его `mattpocock-skills:grilling` и вернись сюда. Решения wayfinder-карты
(`bd show nikitatrubaev-pdj` → Decisions so far) — полноправный вход: не переспрашивать.

## Шаги

### 1. Прочитай затронутый код и решения

Пройди по модулям, которых коснётся работа, по ADR в `docs/adr/` и по закрытым тикетам
wayfinder-карты. Термины бери из `CONTEXT.md` (Запись, Заметка, Кнопка, Пайплайн, Очередь…);
двусмысленный термин, всплывший в разговоре, правь в `CONTEXT.md` тем же ходом.
**Готово:** назван список затронутых слоёв (приложение / GitHub Action / формат репо заметок / STT).

### 2. Прогони ADR-гейт

Сверься со списком тем в `CLAUDE.md` → _ADR-гейт_. Сработал — правь ADR тем же ходом и поставь
его путь в шапку спеки; подпись владельца собирается пачкой на остановке-апруве режима 1 `epic`.
**Готово:** в шапке есть строка `ADR:` — путь к правке или «не затронут».

### 3. Наметь seams

Seam — публичная граница, через которую пишется тест. Предпочитай существующую новой, бери
самую высокую, целься в одну. Решение принимай здесь и записывай в спеку.
**Готово:** каждая граница названа модулем и помечена «существующая» или «новая».

### 4. Напиши файл

`docs/specs/<ГГГГ-ММ-ДД>-<слаг>.md`, по-русски, разделы по порядку:

| Раздел | Что в нём |
|---|---|
| Шапка | Дата, Статус (`черновик` до подписи владельца), `ADR:`, `Эпик:` |
| Проблема | Что не работает у пользователя, его словами |
| Решения | Нумерованный список принятых решений; у продуктовых — чьё решение и когда |
| Скоуп | Экраны, сервисы, форматы, workflow, которых работа касается |
| Не-скоуп (явно) | Что рядом и НЕ делается — пункт на каждое ожидание, которое иначе достроят |
| Критерии приёмки | Проверяемое поведение: действие → наблюдаемый результат |
| Затронутые слои | Из шага 1; чего не касаемся — тоже строкой |
| Решения по тестированию | Seams из шага 3, что здесь считается хорошим тестом |
| Архитектура (HLD) | **Обязателен при 2+ слоях**: компоненты, потоки данных, контракты между слоями |

Пути файлов и куски кода держи вне спеки — они протухают. Исключение: решение, которое
нельзя переоткрывать (формат заметки, контракт Action, параметры Deepgram), — вставь кусок
и подпиши, откуда он.

**Готово:** файл существует, каждый раздел заполнен, ни одного «TBD».

### 5. Свяжи с эпиком

Положи путь спеки в описание bd-эпика: следующие итерации читают его оттуда, а не из
разговора. Эпика ещё нет — впиши путь при заведении срезов скиллом `to-tickets`.
**Готово:** `bd show <эпик>` печатает путь спеки.
