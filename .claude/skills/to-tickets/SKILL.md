# Срезы из спеки

Срез — **узкий, но полный путь через все слои, который можно показать сам по себе**.
Перенесено из workwatch (форма 2, раздел E): срезы не делят файлы, у каждого машинная строка
«Трогает:», набор на круг выдаёт скрипт.

## Шаги

### 1. Возьми спеку

Путь даёт пользователь или `bd show <эпик>`. Прочитай целиком: решения, не-скоуп, критерии приёмки.
**Готово:** выписаны критерии приёмки, которые срезы обязаны закрыть — все до одного.

### 2. Отдели то, что режется, от того, что ведётся expand–contract

Широкий рефактор и смена формата (переименовать поля frontmatter, перекроить папки репо
заметок) в срез не влезают: одна правка ломает все места сразу, и зелёным не будет ни один
срез. Веди их expand–contract: добавить новую форму → перевести читателей партиями →
удалить старую форму отдельной последней задачей.
**Готово:** каждый кусок работы отнесён к «вертикальный срез» или «expand–contract».

### 3. Нарежь срезы

На каждый ответь вопросом **«что я смогу показать, когда это готово?»**. Ответ обязан быть
ПОВЕДЕНИЕМ — «зажал кнопку питания на локскрине, файл записи появился в папке приложения»,
— а не слоем («сервис записи», «клиент Deepgram», «workflow»). Получился слой — срез
горизонтальный, режь заново.

Каждый срез:
- проходит все свои слои — от триггера до наблюдаемого результата;
- демонстрируем или проверяем в одиночку (на телефоне, в тестовом репо, в логе workflow);
- влезает в одно свежее контекстное окно исполнителя;
- размером с постоянную плату агента, не меньше: **срез — одно видимое поведение, не одна
  находка**; находки одного аудита или ревью по одному экрану — один срез. Замер workwatch
  `ww-usgj` 2026-09-02: 28 срезов спеки разрослись до 112 задач по одной на находку, 48
  закрыты без работы — каждая задача платит чтение спеки, дерево, гейты и ревьюера. Наш
  прецедент — эпик v2: 13 открытых хвостов ревью перебиты в четыре среза 2026-09-05;
- префактор («сделай изменение лёгким, потом сделай лёгкое») идёт первым срезом.

**Первый срез — ходячий скелет, а не фундамент.** Тончайший сквозной путь, который уже
показывается: экран открылся и отрисовал пустое состояние. Всё, что можно отложить —
откладывай в следующие срезы.

**Проверь граф на бутылочное горло — командой, а не глазами.** Если от ОДНОГО среза зависят
больше двух других, он слишком жирный, режь его заново.

**Срезы одного эпика не делят файлы.** Общий файл в двух «Трогает:» ставит их в очередь
(`scripts/ready-slices.py`), и параллельность падает до одного. Пересечения проверять командой
до заведения; если общий файл неизбежен — первым срезом разнести его (у нас так копились
`RepoStore.kt`, `Edit.kt`, `GithubClient.kt`: срезы Н5 и Н7 не могли трогать файлы друг
друга и оставили долг задачами).

**Строка «Трогает:» — машинная, её читает скрипт;** журнал среза `docs/plans/<слаг>/<id>.md` в неё не пишется — он свой у каждого среза; форма записана в
`docs/agents/issue-tracker.md`. По ней `scripts/ready-slices.py` набирает непересекающийся
круг исполнителей — по названиям задач это не проверяется, а задача без строки к параллели не
допускается вовсе.

```
Трогает: app/src/main/kotlin/com/roflochinsky/noteapp/pipeline/Edit.kt, app/src/test/kotlin/com/roflochinsky/noteapp/pipeline/EditTest.kt
```

**Готово:** у каждого среза записана одна фраза-поведение и строка «Трогает:» в этой форме; ни
от одного среза не зависят больше двух других; вместе они закрывают критерии приёмки шага 1.
`scripts/ready-slices.py <эпик>` не печатает ни одной задачи с причиной «НЕТ строки «Трогает:»».

### 4. Заведи срезы в beads

По срезу — issue, в порядке зависимостей (блокирующие первыми):

```bash
bd create --parent=<эпик> --type=task --priority=<0-4> \
  --title="<поведение коротко>" \
  --description="Продукт: <ценность одним предложением>

Увидишь: <что владелец увидит работающим>.
<границы среза, чем проверяется, пути спеки и плана>
Трогает: <пути через запятую>"
```

Первая строка описания — ровно `Продукт: …`. Последняя строка — «Трогает:» из шага 3. Куски
кода держи вне описания — исполнитель читает спеку и план по ссылке.
**Готово:** `bd ready --parent <эпик>` печатает срезы без блокировок, у каждого описания
последней строкой стоит «Трогает:».

### 5. Проставь зависимости и открой слот слияния

`bd dep add <срез> <блокирующий-срез>` — по команде на ребро. Ребро ставь только там, где второй
срез действительно нельзя начать раньше. Затем:

```bash
bd swarm validate <эпик>   # граф без циклов; «не больше двух зависимых от одного» — правило выше
bd merge-slot check        # слот один на репозиторий; нет — bd merge-slot create
```

Общие ресурсы-замки (`app/build.gradle.kts`, `AndroidManifest.xml`, фикстуры
`app/src/test/resources/`, `docs/examples/process-notes.yml`, `DESIGN.md`, `CONTEXT.md` и
прочие) держат срезы в очереди даже при непересекающихся путях — список и причины в
`docs/harness/epic.md`.
**Готово:** `bd blocked` показывает ровно те срезы, у которых есть ребро; `bd swarm validate`
и `bd merge-slot check` отвечают без ошибки.

### 6. Сдай разбиение человеку

Напечатай нумерованный список: заголовок среза, «увидишь: <поведение>», «ждёт: <срезы>» или
«берётся сразу». Он уходит владельцу в пачку на апрув (остановка на апрув, режим 1 `epic`).
Родительский эпик оставь как есть — не правь и не закрывай.
**Готово:** список напечатан, у каждого среза есть строка «увидишь».
