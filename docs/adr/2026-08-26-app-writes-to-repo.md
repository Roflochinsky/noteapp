# ADR: приложение пишет в репо — правка, удаление, права токена

Дата: 2026-08-26 · Статус: принято · Решения утверждены владельцем в гриллинге 2026-08-25
(Q5, Q6, Q13, Q21, Q22), карта wayfinder `nikitatrubaev-5dd`, тикеты `nikitatrubaev-5dd.4`
и `nikitatrubaev-5dd.3` · Затрагивает ADR-гейт «хранение аудио и приватность».
Факты об API — `docs/research/github-sync-api.md`.

## Проблема

В v1 приложение только добавляет файлы: один PUT — одна новая заметка. В v2 оно правит и
удаляет чужие (уже обработанные Action) файлы и локальное аудио. Это меняет две вещи под
ADR-гейтом: что именно и по чьей команде исчезает с телефона и из репо, и какие права нужны
токену, который лежит в SharedPreferences личного устройства.

## Решение

**Git — единственный источник правды.** Приложение — клиент: читает через GitHub REST API,
держит локальный кэш, правки отправляет коммитами. Git-клона на телефоне нет.

**Что можно править.** У задачи — всё (статус, приоритет, проект, срок, теги, текст,
подзадачи). У заметки — поля frontmatter (тип, заголовок, проект, участники, теги) и текст
саммари. **Транскрипт не редактируется никогда** — это правда записи.

**Удаление — только по явному выбору владельца.** Диалог перечисляет галочками, что именно
удалить, и по умолчанию отмечен один пункт:

| Пункт | По умолчанию |
|---|---|
| Файл заметки в репо | отмечен |
| Аудио на телефоне | снят |
| Задачи, порождённые этой заметкой | снят |

Удаление задачи — просто её файл. Ничего сверх отмеченного не удаляется: заметка не уносит с
собой ни аудио, ни задачи молча. Диалог честно предупреждает, что откат возможен только через
историю git, а локальное аудио не восстановимо.

**Когда синкаем.** При открытии приложения и по pull-to-refresh. Фонового поллинга нет —
свежесть нужна, когда владелец смотрит в экран, а не круглосуточно (батарея). Правки уходят
сразу; без сети встают в офлайн-очередь v1 (WorkManager) и уходят сами.

**Механика (по фактам research):** чтение — условный запрос ETag на ветку (304 не тратит
лимит) → `compare` → дочитать только изменённые файлы; запись одного файла — contents API со
свежим blob-SHA; **любой жест, задевающий несколько файлов** (удаление заметки вместе с
задачами, перенос, переименование персоны) — **один коммит** через git data API
(blobs → trees → commits → PATCH ref, `force: false`). Ответ 409 (устаревший SHA) — штатная
ветка, а не сбой: перечитать файл, наложить правку заново, повторить; если в git изменилось
**то же самое поле**, побеждает git и владельцу показывается расхождение — молча перезатирать
чужую правку нельзя, с той стороны обычно Action с саммари.

**Токен.** Fine-grained PAT, ограниченный одним репо заметок, право `Contents: Read and write`.
Хранение — прежнее (SharedPreferences MODE_PRIVATE личного устройства, вердикт LLD-1 v1).

## Последствия

- Приложение получает право удалять файлы в репо — раньше могло только добавлять. Защита не
  техническая, а продуктовая: удаление всегда проходит через диалог с явными галочками.
- Аудио остаётся на телефоне после удаления заметки, пока владелец не отметит галочку. Место
  на диске копится — осознанный размен в пользу «ошибка не теряет запись» (принцип 4).
- Каждый коммит приложения запускает Action (коммиты под PAT, не под `GITHUB_TOKEN`), но петли
  «правка → Action → правка» нет: Action работает только на `inbox/**` со `status: raw`.
- После каждой обработанной заметки SHA в кэше телефона протухают — это норма, а не редкий
  угол; ветка 409 обязана быть рабочей с первого дня.

## Отклонено

- **Git-клон на устройстве** (JGit) — тянет мердж-машинерию и хранение всей истории ради
  операций, которые REST закрывает четырьмя запросами.
- **Фоновый поллинг раз в N минут** — расход батареи ради свежести, которую никто не смотрит;
  ETag делает добавку тривиальной, если понадобится.
- **Last-write-wins на конфликте** — молча затирает саммари, которое Claude только что написал.
- **Каскадное удаление** (заметка уносит аудио и задачи) — необратимо и не спрашивает.
- **Отдельный «архив» вместо удаления** — лишняя сущность; история git и есть архив.
