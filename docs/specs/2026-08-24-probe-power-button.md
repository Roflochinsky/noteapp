# Спека: зонд кнопки питания

Дата: 2026-08-24 · Статус: черновик (до апрува владельца) · ADR: не затронут — зонд
проверяет оба механизма триггера, выбор и ADR будут по его результатам · Эпик: (id после
to-tickets; закрывает тикет карты nikitatrubaev-pdj.3)

## Проблема

Ключевая фича v1 — запись по long-press кнопки питания с локскрина — упирается в четыре
OEM-неизвестных OxygenOS 15, которые не решаются документацией (docs/research/assistant-role.md,
раздел Verdict): пункт настройки и сторонний ассистент в пикере; перехват вызова лончером;
поведение при погашенном экране; возможная блокировка VoiceInteractionService у OPPO.
Пока они не проверены на реальном OnePlus 13, писать пайплайн v1 — ставка вслепую.

## Решения

1. Зонд — минимальный APK, но **не одноразовый**: его каркас (Gradle, гейты, ассистент-обвязка,
   FGS записи) становится фундаментом v1 (решение владельца «делать через /epic», 2026-08-24;
   рекомендация research §6).
2. Проверяются **оба** механизма триггера: A — `VoiceInteractionService` (канонический AOSP),
   B — `ACTION_ASSIST`-активити (фолбэк, свидетельство §2.7.1 о блокировке VIS у OPPO).
   Переключение — дешёвое, флагом манифеста/сборки; выбор для v1 делается по результатам P1–P9.
3. Архитектура зонда — по research §6: `AssistService` + `AssistSessionService` +
   `ToggleSession` (setUiEnabled(false), setDisabledShowContext, startForegroundService
   синхронно в onShow, порядок «сначала FGS, потом hide») + `RecordingService`
   (foregroundServiceType="microphone", состояние тумблера здесь) + `DummyRecognitionService`
   (обязателен — иначе роль слетает при каждом installDebug, §1.4a).
4. Прогон на устройстве — по чеклисту **P1–P9** из research; результат каждого P фиксируется
   письменно. Телефон в руках владельца: агент готовит wizard-скрипт с adb-командами, владелец
   выполняет (CLAUDE.md → Окружения и безопасность).
5. Пакет приложения: `com.roflochinsky.noteapp` (ник владельца на GitHub; имя приложения —
   всё ещё туман карты, пакет от него не зависит).
6. Гейты качества — из CLAUDE.md: ktfmt + detekt + Android Lint + testDebugUnitTest;
   первый срез обязан довести их до зелёного и вписать точные команды в CLAUDE.md.

## Скоуп

Gradle-проект в корне noteapp (`app/`), манифест с обоими вариантами триггера, FGS записи
5–30 сек в `files/probe/`, лог-тег `PROBE`, минимальный экран статуса (роль назначена? FGS
жив? последний файл записи), wizard-скрипт прогона, протокол результатов
`docs/research/probe-results.md`.

## Не-скоуп (явно)

- Пайплайн v1: Deepgram, сборка .md, GitHub-пуш, Action — ничего из этого.
- UI по компу «Документ» — у зонда служебный экран, дизайн не применяется.
- Онбординг, разрешения «по-красивому» — разрешения выдаются руками через настройки/adb.
- Выбор механизма триггера и его ADR — только ПОСЛЕ прогона.
- Плитка Quick Settings, виджеты, часы.

## Критерии приёмки

1. `./gradlew ktfmtCheck detekt lint testDebugUnitTest assembleDebug` — зелёный, APK существует.
2. На OnePlus 13: приложение появляется в пикере «Цифровой ассистент» (P1) — либо
   зафиксирован отказ и работает обход `adb shell cmd role add-role-holder`.
3. Long-press питания при включённом экране вызывает `onShow`/активити зонда (P2–P3) — либо
   письменно зафиксирован перехват лончером с логами.
4. Повторный long-press во время записи останавливает её (P5): в `files/probe/` файл с
   ненулевым звуком, в логе — start/stop с session id.
5. Все девять пунктов P1–P9 имеют вердикт в `docs/research/probe-results.md`, включая три
   сценария экрана (P4) и выживаемость 30–60 мин (P7).
6. Итоговая строка протокола: «вариант триггера для v1 — A | B | ни один (фича
   переопределяется)» + что это меняет для карты.

## Затронутые слои

Приложение (Kotlin, новый Gradle-проект) и инструментарий прогона (adb, wizard). Формат
репо заметок, Action, STT — не затронуты.

## Решения по тестированию

Автотестов у зонда минимум — его предмет проверяется только железом. Seams:
- юнит (существующая граница JVM): чистая логика тумблера `ToggleState` (start/stop/повторный
  вызов) — один тест-файл, без Android-зависимостей;
- всё остальное — ручной протокол P1–P9 (это и есть тесты зонда), команды в wizard-скрипте.

## Архитектура (HLD)

Один слой — приложение; HLD не требуется (порог 2+ слоя не достигнут). Схема компонентов —
research §6, повторена в «Решениях» п.3.
