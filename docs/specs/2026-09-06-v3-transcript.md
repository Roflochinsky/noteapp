# Спека v3, часть 1: заметка распознаётся ElevenLabs

Дата: 2026-09-06 · Статус: подписана владельцем 2026-09-06 (ADR) · ADR: `docs/adr/2026-09-06-stt-elevenlabs-scribe-v2.md` · Эпик: `nikitatrubaev-u4g` · Карта: `nikitatrubaev-7cy`

Часть 1 покрывает только смену распознавания. Словарь имён (`7cy.2`), правка транскрипта
(`7cy.3`), разметка перед саммари (`7cy.6`) и прокрут (`7cy.4`) дописываются частями 2+ по
мере закрытия карты — в журнале правок ниже.

## Зачем

Deepgram переписывает разговорную речь и глотает куски: «а чё ты кстати эту систему ввёл
(смех) давай обсудим» приходит как «ты кстати эту систему вёл на судом». Владелец прослушал
запись со всеми вендорами рядом и выбрал ElevenLabs: контекст передан точнее «на пару голов».

## Пример на настоящих данных

Запись 2026-08-26 14:29, 66 минут, трое говорящих. Сейчас в заметке: «Спикер 1: ты кстати эту
систему вёл на судом». После работы: «Спикер 1: Чего ты, кстати, эту систему ввел? [смеется]
Судим.» — с пометкой смеха и верным глаголом.

## Решение 1. Расшифровку делает ElevenLabs Scribe v2

Приложение шлёт запись в ElevenLabs одним запросом и получает слова со спикерами и временем.
Deepgram из пайплайна уходит, но его ключ в настройках не стирается до первой удачной заметки
через ElevenLabs.
Увидишь: записал → в заметке транскрипт от ElevenLabs, в реплике со смехом стоит «[смеется]».

## Решение 2. Параметры запроса одни и те же, что на стенде

Модель `scribe_v2`, русский язык, диаризация, время по словам, события звука. Словаря пока
нет — он приезжает частью 2 (`7cy.2`).
Увидишь: транскрипт заметки совпадает с прогоном `bin/stt-bench` на той же записи.

## Решение 3. Вид заметки не меняется

Реплики «[мм:сс] Спикер N: текст» приложение собирает из слов само: тот же спикер и пауза
короче полутора секунд — одна реплика. Action, лента, старые заметки ничего не замечают.
Увидишь: файл заметки в GitHub выглядит как раньше, только текст точнее.

## Решение 4. Ключ ElevenLabs вводится там же, где вводился ключ Deepgram

Строка настроек и онбординга называется «Ключ ElevenLabs», ключ нужен с правом Speech to
Text; без ключа запись ждёт в очереди, как без ключа Deepgram.
Увидишь: в настройках строка «Ключ ElevenLabs», чек онбординга зелёный после ввода.

## Чего НЕ будет

- Словаря имён: имена как «Семенко» остаются до части 2.
- Перераспознавания старых заметок.
- Правки транскрипта, прокрута и разметки перед саммари.
- Смены формата заметки или промпта Action.

## Что нужно от владельца

Ключ ElevenLabs с правом Speech to Text вставить в приложение после установки APK (телефон —
не стенд, ставит владелец). Больше ничего: ADR подписан.

## Критерии приёмки

1. Записать 30-секундную заметку с ключом ElevenLabs → в репо заметок появляется `.md` с
   репликами `[мм:сс] Спикер N: …`, `transcript.json` рядом — ответ ElevenLabs целиком (Решение 1, 3).
2. Тот же файл, что гоняли на стенде → реплики заметки совпадают со сборкой
   `bin/stt-compare-html` по тексту и первым таймкодам (Решение 2, 3).
3. Ответ с `audio_event` → в тексте реплики `[смеется]` (Решение 1).
4. Ответ Deepgram, лежащий в старом `transcript.json` → читается как прежде, экран заметки не
   падает (Решение 3).
5. Ключа нет → запись ждёт в очереди со статусом «нет ключа», после ввода уходит сама (Решение 4).
6. Ошибка 401/400 от ElevenLabs → запись не теряется, статус с текстом ошибки, повтор по тапу (Решение 1).

## Затронутые слои

| Слой | Что меняется |

| Приложение | клиент STT, разбор ответа, воркер распознавания, настройки и онбординг (Решение 1, 2, 4) |
| Формат репо заметок | не меняется; `transcript.json` получает форму ElevenLabs (Решение 3) |

## Seams

- `TranscriptMapper.fromElevenLabsJson(json): Transcript` — новая, рядом с
  `fromDeepgramJson` (существующая, остаётся для старых `transcript.json`). Тест на фикстуре
  `app/src/test/resources/elevenlabs-sample-response.json`, снятой со стенда (обрезанной).
- `ElevenLabsClient.transcribe(audio, key): String` — новая, по образцу `DeepgramClient`;
  тестируется офлайн разбором multipart-тела (повторяющиеся поля) и кодов ошибок.
- `TranscribeWorker` — существующий шов: выбор клиента по наличию ключа.

## Замороженные контракты

Запрос: `POST https://api.elevenlabs.io/v1/speech-to-text`, заголовок `xi-api-key`, multipart
поля `file`, `model_id=scribe_v2`, `language_code=rus`, `diarize=true`,
`timestamps_granularity=word`, `tag_audio_events=true`; `keyterms` — повторяющимися полями,
только с частью 2. Ответ: `words[]` с `text`, `start`, `end`, `type ∈ {word, spacing,
audio_event}`, `speaker_id`. Реплика: тот же `speaker_id`, пауза `< 1.5 с`; `audio_event` —
в квадратных скобках как пришло.

## Бюджеты

- От «стоп» до транскрипта в приложении: ≤ 3 мин на часовую запись (стенд: 70–97 с плюс
  загрузка 48 МБ), ≤ 30 с на пятиминутную.
- Запросов к ElevenLabs на одну запись: ровно 1 (без опроса готовности); повтор только по
  ошибке или тапу.
- Экран заметки держит транскрипт на 66 минут (≈ 500 реплик, 18 000 слов в JSON) без
  заметной задержки при открытии.
- Батарея: воркер по-прежнему один запрос в фоне, ничего не опрашивает.

## Проверка на стенде

- **Смоук на тестовом репо** `Roflochinsky/voice-notes-test`: `NoteSmokeTest` с переменной
  `NOTEAPP_SMOKE_TOKEN` и ключом ElevenLabs из окружения — заметка доехала, форма реплик верна.
- **Прокликка на телефоне** (владелец): ввести ключ ElevenLabs → записать 30 с со смехом →
  открыть заметку → увидеть «[смеется]» → открыть файл в GitHub.
- **Сверка с артефактом дизайна**: экранов срез не меняет; строка настроек — по `DESIGN.md`,
  как строка «Ключ Deepgram».
