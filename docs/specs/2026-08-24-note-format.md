# Спека: формат заметки, структура репо, промпт Action

Дата: 2026-08-24 · Статус: утверждено владельцем (Q1–Q5, 2026-08-24) · ADR: формат заметки
и контракт Action — под ADR-гейтом (CLAUDE.md), заводится при первой реализации · Эпик v1.

**Поправка v2 (2026-08-26, срез `nikitatrubaev-0rk.4`).** Решение Q5 переиграно ADR
`docs/adr/2026-08-26-tasks-as-files.md`: задача — отдельный файл в `tasks/`, а в теле заметки
секция «Задачи» стала списком ссылок на эти файлы. Ниже по тексту это уже учтено; всё
остальное (raw-формат, перенос в папку типа, триггер) v1 и v2 делят без изменений.

## Проблема

После «стопа» телефон должен сложить заметку так, чтобы GitHub Action смог дописать саммари
и разложить по типам, а человек — читать это в GitHub/Claude. Нужен точный контракт между
телефоном (пишет raw) и Action (пишет смысл).

## Решения (приняты владельцем)

1. **Два состояния файла.** Телефон пушит `raw` в `inbox/`; Action обрабатывает и переносит
   в папку типа. Видно, что обработано, а что ещё в очереди. (Q1)
2. **Имя файла** `ГГГГ-ММ-ДД-ЧЧММ.md` от телефона; Action добавляет слаг из темы →
   `ГГГГ-ММ-ДД-ЧЧММ-слаг.md`. Сортировка по дате. (Q2)
3. **Разделение труда.** Телефон знает только `recorded`, `duration`, `device` и транскрипт
   со «Спикер N» + тайм-коды (из Deepgram utterances). Тип, участники, заголовок, слаг,
   саммари, задачи — всё определяет Claude в Action. (Q3)
4. **Триггер Action** — `on: push` по путям `inbox/**`. Мгновенно после пуша. (Q4)
   Реализация — релей push → `workflow_dispatch`, т.к. `claude-code-action` событие
   `push` не поддерживает; см. ADR `docs/adr/2026-08-25-action-trigger-relay.md`.
5. ~~**Задачи** — `- [ ]` в теле заметки (секция Задачи саммари). Сводный список по репо — v2.~~ (Q5)
   **Переиграно в v2** (ADR `2026-08-26-tasks-as-files.md`): задача — отдельный файл
   `tasks/ГГГГ-ММ-ДД-слаг.md`, в заметке остаются только ссылки на них. Статус задачи живёт
   в файле задачи, чекбоксов-дублей в заметке нет.
6. Типы (папки): `встречи/ идеи/ задачи/ личное/ другое/` (термин «встреча» и пр. — CONTEXT.md).
7. Аудио в git не пушится (решение карты). Один пуш = одна заметка.

## Формат raw (пишет телефон)

```markdown
---
recorded: 2026-08-24T18:07:32+03:00   # ISO-8601 с таймзоной телефона
duration: 12:31                        # мм:сс или чч:мм:сс
device: OnePlus 13
status: raw
---

## Транскрипт

[00:12] Спикер 1: <реплика из Deepgram utterances[].transcript>
[00:31] Спикер 2: <реплика>
```

Маппинг из Deepgram (nova-3, multi): `utterances[].speaker` (0,1,…) → «Спикер N+1»;
`utterances[].start` → тайм-код `[мм:сс]`; `utterances[].transcript` → текст реплики.

## Формат done (пишет Action поверх raw)

```markdown
---
recorded: 2026-08-24T18:07:32+03:00
duration: 12:31
device: OnePlus 13                     # поля raw сохраняются как есть
type: встреча                          # один из пяти типов
participants: [Дима, Никита]           # сверены с people.md; незнакомые остаются как услышаны
project: tgsum                         # v2: слаг из projects.md; опускается, если проекта нет
tags: [релиз]                          # v2: свободные слова; опускается, если тегов нет
title: Созвон — релиз tgsum
status: done
---

## Саммари
**Суть.** <1–3 предложения.>

**Ключевое.**
- <пункт>

**Задачи.**
- [<заголовок задачи>](../tasks/<ГГГГ-ММ-ДД-слаг>.md)   # секция опускается, если задач нет

## Транскрипт

[00:12] Спикер 1: …
```

Блоки саммари разделены пустой строкой — без неё GitHub слепляет их в один абзац.
Секция «Задачи» — **только ссылки** на файлы в `tasks/`; чекбоксов `- [ ]` в заметке не
остаётся, статус задачи живёт в её файле (ADR `2026-08-26-tasks-as-files.md`, там же схема
frontmatter задачи — дублировать её здесь нельзя). Секция «Транскрипт» переносится из raw
как есть, вместе с пустой строкой после заголовка: Action транскрипт не переписывает.

Файл переносится: `inbox/2026-08-24-1807.md` → `встречи/2026-08-24-1807-reliz-tgsum.md`.

## Промпт Action (claude-code-action, OAuth Max-подписки)

Промпт целиком живёт в эталоне `docs/examples/process-notes.yml` — это единственная его
редакция; пересказ ниже даёт суть, при расхождении прав эталон.

> Ты обрабатываешь новые голосовые заметки. Для каждого файла в `inbox/` со `status: raw`:
> прочитай транскрипт, определи `type` (ровно один из: встреча, идея, задача, личное, другое),
> `participants` (имена из разговора, сверенные с `people.md`; пустой список, если нет),
> `project` (слаг из `projects.md`, иначе поле опустить), `tags`, короткий `title` и слаг для
> имени файла (латиница, kebab-case, из темы). Добавь секцию `## Саммари` сверху
> (Суть / Ключевое). Проставь мету, смени `status` на `done`, перемести файл в папку
> `<type в мн.числе>/` с именем `<та же дата-время>-<слаг>.md`. **После переноса** вытащи
> задачи в файлы `tasks/` (`source:` — конечный путь заметки) и впиши их в саммари блоком
> «Задачи» ссылками; задач нет — секции нет. Реестры не пополняй, существующие файлы в
> `tasks/` не трогай. Транскрипт не переписывай. Коммить по-русски.

Эталонная пара «как выглядит результат» — `app/src/test/resources/action/`; промпт меняется
только вместе с ней.

## Скоуп / Не-скоуп

- Скоуп: контракт raw↔done, раскладка репо, триггер и промпт Action.
- Не-скоуп (v2): сводный файл задач, README-оглавление, автоотправка в Telegram, теги вручную.

## Критерии приёмки

1. Телефон пишет валидный raw-файл указанной структуры; парсится как YAML frontmatter + md.
2. Action на push в `inbox/` доводит файл до done-формата и переносит в папку типа.
3. Спикеры и тайм-коды в транскрипте соответствуют Deepgram utterances.
4. Если задач нет — секции Задачи нет; если участников нет — `participants: []`.

## Затронутые слои

Приложение (сборка raw + пуш) и GitHub Action. STT — вход (формат utterances). Аудио — нет.
