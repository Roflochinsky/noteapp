# Спека v2: задачник поверх заметок

Дата: 2026-08-26 · Статус: черновик (ждёт подписи владельца на остановке-апруве `/epic`) ·
ADR: `docs/adr/2026-08-26-tasks-as-files.md`, `docs/adr/2026-08-26-app-writes-to-repo.md` ·
Эпик: заводится `to-tickets` из этой спеки · Карта решений: `bd show nikitatrubaev-5dd`.

## Проблема

Заметки копятся, задачи из них — нет. Сейчас задача существует как строка-чекбокс внутри
саммари: её не найти списком, не отфильтровать по рабочему проекту, не отметить сделанной с
телефона. Владелец хочет видеть все задачи одним списком — как в beads-hub: с фильтром по
проекту, приоритету и сроком, с подзадачами внутри задачи. Заодно приложение должно уметь
править и удалять то, что уже лежит в репо: сейчас оно умеет только добавлять новое, а
исправить услышанное Claude имя или снести лишнюю заметку можно лишь в GitHub с компьютера.

## Решения

Все решения приняты владельцем в гриллинге 2026-08-25 (Q1–Q25) и утверждении компа 2026-08-26;
факты об API — `docs/research/github-sync-api.md` (тикет `nikitatrubaev-5dd.2`).

1. **Задача — отдельный `.md`-файл** в `tasks/` репо заметок: `ГГГГ-ММ-ДД-слаг.md`,
   frontmatter `title / project / priority / status / source / created / due / tags`.
   Подзадачи — чекбоксы внутри файла, один уровень. (Q2, Q11, Q15, Q23–Q25; ADR tasks-as-files)
2. **Задачи рождаются двумя путями**: Action извлекает их из транскрипта; владелец создаёт
   руками в приложении. Голос — главный путь, ручной — обязательный. (Q3)
3. **Проект и Персона — метки с реестрами** `projects.md` и `people.md` в корне репо,
   markdown-списками. Теги — свободные слова без реестра. (Q4, Q12, Q16, Q24)
4. **Action новых персон в реестр не добавляет** — незнакомое имя остаётся в тексте, решение
   за владельцем. (Q17)
5. **Статус задачи живёт только в файле задачи**; в заметке секция «Задачи» — ссылки на
   файлы. (Q18)
6. **Action не трогает done-заметки и `tasks/`** — работает только на `inbox/**` со
   `status: raw`; правки владельца не затираются, саммари не перегенерируется. (Q19)
7. **Git — единственный источник правды**, приложение — клиент GitHub API с локальным кэшем;
   git-клона на телефоне нет. (Q5; ADR app-writes-to-repo)
8. **Правится**: задача — целиком; заметка — поля frontmatter и текст саммари; транскрипт —
   никогда. (Q6)
9. **Удаление — диалог с галочками** (файл в репо / аудио на телефоне / порождённые задачи),
   по умолчанию отмечен только файл в репо. (Q6, Q13)
10. **Синк при открытии приложения и pull-to-refresh**, фонового поллинга нет; правки уходят
    сразу, без сети — в офлайн-очередь v1. (Q21)
11. **Конфликт 409 — штатная ветка**: перечитать, наложить правку заново, повторить; при
    правке того же поля побеждает git и владельцу показывается расхождение. Мультифайловый
    жест — один коммит через git data API. (Q22)
12. **Фильтры**: лента заметок — тип, проект, персона, тег, дата; задачи — проект, приоритет,
    статус, тег, срок. Чипы под шапкой, значения из реестров. (Q7, комп)
13. **UI — комп «Документ» v2**, утверждён владельцем 2026-08-26:
    https://claude.ai/code/artifact/148e45f8-93e0-492d-b63c-be1c1799e43a — переключатель
    «Заметки | Задачи» вкладками в шапке, задачи плоским списком по приоритету (рубрики
    P1/P2/P3, просрочка янтарём, «Сделано» свёрнуто), деталка задачи с сегментом статуса,
    деталка заметки с полями-чипами. Система мира — `DESIGN.md`. (`nikitatrubaev-5dd.3`)
14. **Миграция** существующих done-заметок — разовый прогон: чекбоксы «Задач» → файлы
    `tasks/` + ссылки. (Q20)
15. **Токен** — fine-grained PAT на один репо заметок, `Contents: Read and write`. (research §9)

## Скоуп

- **Экран задач**: список с рубриками приоритета, чипы-фильтры, свёрнутое «Сделано»,
  создание задачи шторкой, деталка задачи (статус, поля, подзадачи, ссылка на источник).
- **Лента заметок**: переключатель вкладок, чипы-фильтры, значения из реестров.
- **Деталка заметки**: правка полей (тип, проект, участники, теги), правка текста саммари,
  задачи ссылками, удаление.
- **Диалог удаления** с галочками — для заметки и для задачи.
- **Выбор персон** из реестра с предложениями Claude; переименование персоны — один коммит по
  реестру и всем заметкам с ней.
- **Слой синка**: чтение репо (ETag → compare → изменённые файлы), кэш, запись одного файла,
  батч-коммит, разбор 409, офлайн-очередь.
- **Формат репо заметок v2**: `tasks/`, `projects.md`, `people.md`, поля `project`/`tags` у
  заметки.
- **Action v2**: извлечение задач в файлы, ссылки вместо чекбоксов, сопоставление персон с
  реестром; эталон `docs/examples/process-notes.yml` и рабочая копия — синхронно.
- **Миграция** существующих заметок.

## Не-скоуп (явно)

- **Перегенерация саммари** после ручной правки заметки — Action не возвращается к
  done-файлам вовсе.
- **Правка транскрипта** в приложении.
- **Подзадачи со своими полями и вложенность глубже одного уровня.**
- **Сводный вид задач на стороне GitHub** (`TASKS.md`, README-оглавление) — в приложении есть
  экран, дублировать индексом незачем.
- **Фоновый поллинг и push-уведомления** об изменениях в репо.
- **Реестр тегов** и переименование тегов пачкой.
- **Совместная работа**: чужие правки других людей, назначение задач на кого-то, поле
  «ответственный».
- **Повторяющиеся задачи, напоминания, календарь, время суток у срока.**
- **Git-клон на устройстве, работа с ветками, разрешение мерж-конфликтов вручную.**
- Всё не-скоупное из v1 (Play Store, iOS, офлайн-STT, диаризация on-device) остаётся в силе.

## Критерии приёмки

Проверяемое поведение — действие владельца → наблюдаемый результат.

**Задачи**

1. Открыть вкладку «Задачи» → список открытых задач, сгруппированный рубриками P1/P2/P3;
   просроченные подписаны янтарным «просрочено», сделанные скрыты в свёрнутом «Сделано».
2. Тап чипа «Проект» → шторка со списком проектов из `projects.md` и счётчиками; выбор
   проекта сужает список; активный чип показывает выбранное значение и крестик сброса.
3. Тап по чекбоксу задачи → задача помечается сделанной, уходит в «Сделано», в репо появляется
   коммит с `status: done` в её файле.
4. В деталке задачи сменить приоритет, проект, срок, добавить тег, отметить подзадачу →
   каждое изменение видно в файле `tasks/…md` в GitHub; подзадачи остаются чекбоксами внутри.
5. «Новая задача» → введённый текст создаёт файл `tasks/ГГГГ-ММ-ДД-слаг.md` со `status: open`
   и `priority: P2` по умолчанию, одним коммитом.
6. У задачи, рождённой из заметки, есть ссылка на заметку-источник, и она открывает эту
   заметку в приложении.

**Заметки**

7. Записать заметку с задачами в разговоре → после работы Action в `tasks/` лежат файлы задач,
   а в теле заметки на их месте — ссылки; чекбоксов-дублей в заметке нет.
8. Фильтры ленты по типу, проекту, персоне, тегу и дате сужают ленту; значения персон и
   проектов приходят из реестров.
9. В деталке заметки сменить тип, проект, участников (из реестра) и теги → изменения видны во
   frontmatter файла в GitHub; транскрипт в приложении не редактируется.
10. Правка текста саммари сохраняется в файл и **не** перезапускает Action.
11. Переименовать персону в приложении → одним коммитом обновлены `people.md` и все заметки,
    где она была участником.

**Удаление**

12. Удалить заметку с настройками по умолчанию → из репо исчезает только её файл; аудио на
    телефоне и порождённые задачи остаются.
13. Отметить в диалоге все три галочки → одним коммитом исчезают файл заметки и файлы её
    задач, локальное аудио удалено с телефона.

**Синк и конфликты**

14. Обработка Action завершилась, пока приложение открыто → pull-to-refresh показывает
    саммари и новые задачи; при отсутствии изменений обновление не тратит лимит API (304).
15. Править задачу без сети → правка встаёт в очередь, приложение показывает это, при
    появлении сети коммит уходит сам.
16. Правка при устаревшем SHA (Action изменил файл параллельно) → приложение переигрывает
    коммит молча; если в git менялось то же поле — показывает расхождение и не затирает.
17. Миграция: разовый прогон превращает чекбоксы «Задач» в существующих заметках в файлы
    `tasks/` и ссылки; ни одна заметка не теряет текст.

## Затронутые слои

| Слой | Что меняется |
|---|---|
| Приложение (Kotlin/Compose) | Новый экран задач и его деталка; фильтры и переключатель вкладок в ленте; правка полей и саммари в деталке заметки; диалог удаления; выбор персон; слой синка (чтение репо, кэш, батч-коммиты, 409, очередь) |
| Формат репо заметок | `tasks/`, `projects.md`, `people.md`, поля `project`/`tags` у заметки — ADR tasks-as-files |
| GitHub Action | Промпт v2: извлечение задач в файлы, ссылки вместо чекбоксов, сопоставление персон с реестром; эталон `docs/examples/process-notes.yml` |
| Разовая миграция | Прогон по существующим done-заметкам |
| **STT / Deepgram** | **не касаемся** — параметры и формат транскрипта из v1 без изменений |
| **Триггер записи и ассистент-роль** | **не касаемся** — запись, `RecordingService`, уведомление работают как в v1 |
| **Хранение аудио** | меняется только удаление по явной галочке; путь и политика хранения — как в v1 |

## Решения по тестированию

Seams — публичные границы, через которые пишется тест. Продолжаем линию v1: сеть и Android
остаются снаружи, разбор и решения выносятся в чистые объекты (как `RawNote`,
`DoneNoteParser`, `TranscriptMapper` — у них уже есть юнит-тесты).

| Seam | Существующая / новая | Что закрывает |
|---|---|---|
| `TaskFile` | новая | Разбор и сборка файла задачи: frontmatter, необязательные поля, подзадачи-чекбоксы, круговой прогон «разобрать → собрать → тот же текст» |
| `DoneNoteParser` | существующая | Новые поля `project`/`tags`, секция «Задачи» как ссылки вместо чекбоксов; старые заметки без новых полей продолжают разбираться |
| `Registry` | новая | Разбор и запись `projects.md` / `people.md`; переименование персоны как преобразование текста |
| `RepoDelta` | новая | Из ответа `compare` — список действий над кэшем (добавлено / изменено / удалено / переименовано) и признак «нужен полный пересбор дерева» |
| `ConflictRule` | новая | Решение по 409: то же поле менялось в git или нет → «переиграть молча» либо «показать расхождение» |
| `TaskFilter` | новая | Фильтрация и сортировка списка: приоритет → срок, просрочка, свёрнутые сделанные, комбинация чипов |
| `GithubClient` | существующая | Расширяется (чтение дерева, обновление, удаление, батч-коммит). Юнитами не покрывается — проверяется смоук-прогоном на **тестовом** репо, не на боевом |

Хороший тест здесь — на реальном куске `.md` (фикстура из репо заметок), проверяющий
наблюдаемое поведение границы, а не внутренности. Юнит-тесты гоняются в
`testDebugUnitTest`; сетевые сценарии (14–17) проверяются вручную на тестовом репо и
показываются на реальном OnePlus 13, как срезы v1.

## Архитектура (HLD)

```
                       ┌───────────── приложение (Compose) ─────────────┐
  вкладки              │  Лента заметок        Экран задач              │
  фильтры-чипы         │      │                    │                   │
                       │      └──── FilterState ───┘                   │
                       │                 │                             │
  правка/удаление ────►│  TaskFile · DoneNoteParser · Registry (чистые) │
                       │                 │                             │
                       │            RepoCache (файлы + карта sha)       │
                       │                 │                             │
                       │   SyncEngine: ETag→compare→RepoDelta           │
                       │               ConflictRule (409)               │
                       │               очередь записи (WorkManager)     │
                       └─────────────────┬─────────────────────────────┘
                                         │ GitHub REST API (fine-grained PAT)
                                         ▼
   репо заметок:  inbox/  ·  встречи|идеи|задачи|личное|другое/  ·  tasks/
                  projects.md  ·  people.md
                                         │ push в inbox/**
                                         ▼
                        GitHub Action (claude-code-action):
                        raw → саммари + мета + задачи в tasks/ + ссылки
                        (done-заметки и tasks/ больше не трогает)
```

**Контракты между слоями.**

- **Приложение → репо (чтение):** `GET /git/ref/heads/main` с `If-None-Match` (304 бесплатен)
  → при сдвиге ветки `GET /compare/{lastSha}...{newSha}` → `RepoDelta` → дочитать только
  изменённые файлы. Холодный старт — `zipball` + `git/trees?recursive=1`. Состояние на
  телефоне: `lastCommitSha`, ETag, карта `путь → blobSha`, кэш текстов.
- **Приложение → репо (запись):** один файл без переноса — `PUT /contents/{path}` со свежим
  SHA; мультифайловый жест — blobs → trees(`base_tree`) → commits → `PATCH ref`
  (`force: false`). Очередь записи однопоточная, ≥1 с между мутациями. После записи — сразу
  опрос ref (свой коммит подвинул ветку).
- **Репо → Action:** без изменений — `push` в `inbox/**`, релей в `workflow_dispatch`
  (ADR `2026-08-25-action-trigger-relay.md`).
- **Action → репо:** пишет саммари и мету в заметку, создаёт файлы в `tasks/`, ставит ссылки,
  переносит файл из `inbox/` в папку типа. Реестры и done-заметки — только чтение.
- **Формат файлов** — ADR `2026-08-26-tasks-as-files.md` (единственное место, где живёт схема
  frontmatter; в коде дублировать нельзя).

**Порядок сборки.** Формат и Action — первыми (без них задачам неоткуда взяться), затем слой
синка на чтение (список задач появляется на экране), потом запись (правка/создание), затем
удаление и переименование персон (мультифайловые коммиты), миграция — последней, когда формат
устоялся. Срезы режет `to-tickets`, каждый — одно демонстрируемое поведение на реальном
телефоне.
