# Issue tracker: beads (bd)

Задачи этого репозитория живут в **beads** (`bd`), workspace домашний (id вида
`nikitatrubaev-xxx`). Скиллы `to-spec`, `to-tickets`, `epic`, `epic-orca`, `wayfinder` читают и
пишут сюда; TodoWrite и markdown-TODO не используются. Перенесено из workwatch
(`docs/agents/issue-tracker.md`) 2026-09-05.

## Соглашения

- **Задача** — bd-issue. Иерархия: эпик → дети-срезы (`bd create … --parent=<epic-id>`),
  id ребёнка дотированный: `nikitatrubaev-0rk.5`.
- **Задача — только срез спеки** (одно видимое поведение), находки ревью задачами не
  становятся — они живут в вердикте (`docs/harness/epic.md`). Исключения — класс `a` вне
  среза и вопрос владельцу.
- **Спека** — файл `docs/specs/<ГГГГ-ММ-ДД>-<слаг>.md`, две части (`to-spec`). В трекере на неё
  ссылается описание эпика.
- **План** — файл `docs/plans/<ГГГГ-ММ-ДД>-<слаг>.md`, тот же слаг. В нём вердикты ревью
  замысла, сшитые журналы срезов и ретро.
- **Журнал среза** — свой файл `docs/plans/<слаг>/<id>.md`: его пишет исполнитель
  нарастающим итогом, ревьюер кладёт вердикт рядом (`<id>-review.md`), ведущий сшивает в план
  при закрытии среза. Так план перестаёт быть общим файлом параллельных исполнителей.
  Полный вывод гейтов — в скратчпад сессии (`.gitignore` не пускает `*-gates.txt` в `docs/plans/`).
- **«Трогает:»** — последняя строка ОПИСАНИЯ задачи, машинная форма: полные пути от корня
  репозитория через запятую, каталог с завершающим `/`, без фигурных скобок и пояснений.
  По ней считается параллельность (`scripts/ready-slices.py`), задача без неё не выдаётся.
  ```
  Трогает: app/src/main/kotlin/com/roflochinsky/noteapp/pipeline/Edit.kt, app/src/test/kotlin/com/roflochinsky/noteapp/pipeline/EditTest.kt
  ```
  Журнал среза (`docs/plans/<слаг>/<id>.md`) в строку не пишется — он свой у каждого среза.
- **Описание задачи** — по-русски. Первая строка — `Продукт: <ценность одним предложением>`,
  затем пустая строка, `Увидишь: …`, техчасть (границы, чем проверяется, ссылки на спеку/план),
  последняя строка — «Трогает:».
- **Статус** — `bd update <id> --claim` при взятии (хук `orca-card-sync` двигает карточку
  Orca, когда сессия идёт в её панели), `bd update <id> --status=blocked` с причиной в плане
  при остановке, `bd close <id> --reason="…"` после слияния и показа поведения.
- **Комментарии** (`bd comments add`) в git-экспорт НЕ попадают. Всё, что должно пережить
  сессию и быть видно глазами, идёт в план или журнал среза.
- **Память** — `bd remember` для устойчивых знаний между сессиями (`CLAUDE.md` домашний);
  `bd memories <слово>` для поиска.

## Когда скилл говорит «publish to the issue tracker»

Завести bd-issue: `bd create --title="…" --description="…" --type=task|bug|feature|epic --priority=<0-4>`.
Для среза эпика добавить `--parent=<epic-id>`. Спеку при этом положить файлом в `docs/specs/`
и сослаться на неё из описания.

## Когда скилл говорит «fetch the relevant ticket»

`bd show <id>` (плюс `bd show <id> --json` для машинного чтения). Что можно брать в работу —
`bd ready`; что заблокировано — `bd blocked`. Полезные флаги `bd ready`: `--parent <эпик>`,
`--explain` (почему готова или заблокирована), `--claim` (атомарно взять первую готовую —
снимает гонку двух ведущих), `--json`.

## Зависимости

`bd dep add <issue> <depends-on>` — задача зависит от второй. Заблокированной считается та, у
которой есть незакрытые зависимости; `bd ready` их не показывает.

`bd swarm validate <эпик>` — перед первым диспатчем: дети эпика образуют граф без циклов.
Правило «не больше двух зависимых от одного среза» проверяет ведущий (`to-tickets`).

## Слот слияния

`bd merge-slot` — встроенный замок «один агент за раз», ровно про наше «слияние в `main` идёт по
одному». Очередь слияний живёт в нём, а не в тексте плана (текст умирает при сжатии контекста).

- `bd merge-slot create` — один раз на репозиторий; при старте эпика — `check`, и только если
  слота нет — `create`;
- `bd merge-slot acquire` / `release` — вокруг слияния среза;
- `bd merge-slot check` — перед выдачей задачи, чьи файлы входят в сливаемый срез.

**Не домерено:** поведение `merge-slot` и `swarm validate` в нашей конфигурации Dolt —
проверяется на первом эпике после переноса.

## Устройство beads

Задачи живут в локальной Dolt-БД; синхронизация — через `refs/dolt/data` на git-remote;
`.beads/issues.jsonl` — пассивный экспорт (в этом репо `.beads/` в `.gitignore`, экспорт не
ведётся). Подробности и антипаттерны:
https://github.com/gastownhall/beads/blob/main/docs/SYNC_CONCEPTS.md

## Wayfinding operations (для `/mattpocock-skills:wayfinder`)

- **Карта** — bd-эпик с меткой `wayfinder:map`. Тело: Destination / Notes / Decisions so far /
  Not yet specified / Out of scope. Карты noteapp: v1 `nikitatrubaev-pdj` и v2
  `nikitatrubaev-5dd` (закрыты), v3 `nikitatrubaev-7cy` (активна).
- **Тикет карты** — дочерний issue с меткой `wayfinder:research|prototype|grilling|task`
  (`--no-inherit-labels`). Тело — вопрос под заголовком `## Question`.
- **Блокировки** — `bd dep add <ticket> <blocking-ticket>`.
- **Фронтир** — `bd ready`: открытые, незаблокированные, невзятые.
- **Резолюция** — ответ дописывается в заметки (`bd update <id> --append-notes="## Answer …"`),
  задача закрывается с `--reason`, в описание карты добавляется строка в Decisions so far.
- Решения карты — вход `to-spec`; решения, которых на карте нет, снимает `discuss`.
