## Рубрика оси «стандарты»

Конвенции репозитория плюс **линза над-инженерии**:

- спекулятивные абстракции — устройство под потребителя, которого в срезе нет;
- переизобретённая стандартная библиотека;
- мёртвая гибкость — параметр, ветка или список, у которых один вызов;
- хелпер под одного потребителя;
- нарушены ли четыре правила границ правки (они в задании исполнителя): правка соседнего кода
  «заодно», устройство без второго потребителя, тест не по образцу соседей, тест как задание
  вместо мерила.

Отдельно по этому репозиторию:

- KDoc по-русски и по делу, как у соседей (`GithubClient.kt`, `PipelineQueue.kt`): объясняет
  ПОЧЕМУ, а не пересказывает код;
- ошибки обрабатываются на границах системы, внутреннему коду доверяют;
- тесты экранов — Robolectric с `@GraphicsMode(GraphicsMode.Mode.NATIVE)`; без него текст
  меряется как 1px на символ и проверки геометрии врут;
- имена тестов и структура — как у соседних файлов слоя;
- ktfmt и detekt зелёные (видно в выводе гейта) — но зелёный линтер не отменяет чтения глазами.

## Твои пункты вердикта

1. **ГЕЙТЫ.** Принимаешь по sha из журнала: HEAD дерева совпал с заявленным, копия чистая, своих
   правок нет, файл вывода есть → «приняты по `<sha>`». Не совпало — скажи, сам не гоняй.
2. **ГРАНИЦЫ.** Что стражи среза ВИДЯТ и какой долг объявлен. Список обходов никогда не полный —
   пиши, что тест видит, а не «покрыто». Страж, отбирающий цели по имени файла или по строке,
   дырявый по построению — скажи это.

## Форма отчёта

Пиши нарастающим итогом в файл основного дерева через шелл (инструмент `Write` в чужое дерево не
пускает):

```
cat > /home/nikitatrubaev/code/noteapp/docs/plans/2026-09-06-v3-transcript/nikitatrubaev-u4g.1-review-std.md <<'EOF'
...
EOF
```

Шапка: `## Ревью среза nikitatrubaev-u4g.1 — ось СТАНДАРТЫ`, строка «ревьюер, модель, усилие,
дерево», затем пункты 1–2 выше, затем:

**НАХОДКИ.** `<файл>:<строка>` — что — почему нарушение (правило и где записано) — предлагаемый
класс (`a`/`t`/`b`/`c`/`d`/`e` по таблице `docs/harness/epic.md`; класс утверждает ведущий).
Либо «находок нет». **Сообщай ВСЕ находки, без отбора по важности** — фильтрация это работа
ведущего. Находка без приложенной мутации или замера будет понижена до `b`, поэтому прикладывай:
для стиля довод — строка конвенции, для геометрии и производительности — замер.

Итог одной строкой: `APPROVE` | `CHANGES REQUESTED` (только за конкретное неверное поведение с
примером вход → выход) | `ВЛАДЕЛЬЦУ`.

Порог `CHANGES REQUESTED`: класс `a`; `t`, прикрывающая `a` того же среза; `e`, если предмет
среза и есть документ. Остальное — `APPROVE` с находками в вердикте.

Своих сабагентов не запускай. Отчёт в чат — короткий: вердикт, число находок, путь файла.
