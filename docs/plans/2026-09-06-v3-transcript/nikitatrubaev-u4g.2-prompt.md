### Четыре правила границ правки

1. **Границы правки.** Меняй ровно то, что требует срез; соседний код оставляй как есть, даже
   если видишь, что его можно улучшить. Найденное попутно — строкой «на будущее» в отчёте.
2. **Минимум устройства.** Хелпер, интерфейс или настройка появляются только под второго
   потребителя, который есть в срезе. Ошибки обрабатывай на границах системы (ввод владельца,
   ElevenLabs, GitHub API, файлы репо заметок); внутреннему коду доверяй.
3. **Тесты — по образцу соседей.** Тест пишется там и такого размера, как соседние файлы в
   `app/src/test/kotlin/…`; экраны — Robolectric с `@GraphicsMode(GraphicsMode.Mode.NATIVE)`
   (`CLAUDE.md` → _Тесты экранов_): без него текст меряется как 1px на символ и любая проверка
   геометрии либо врёт, либо проходит сама собой. Этот срез — класс «тихая и дорогая ошибка»
   (очередь и повторы пайплайна): он получает отдельные файлы-стражи.
4. **Тест — мерило, а не задание.** Решай задачу в общем виде. Требование невыполнимо или тест
   неверен — скажи это в отчёте, не подгоняй.

## Что делаем

Сегодня заметка, которая не расшифровалась, выглядит одинаково во всех случаях: в ленте висит
«в очереди — расшифровка», и владелец не может отличить «нет сети» от «нет ключа» и от «ключ
неверный». Хуже: без ключа воркер сдаётся, и запись не уходит даже после того, как ключ введён.

Срез делает три вещи: **статус видно словами**, **запись не теряется**, **после ввода ключа она
уходит сама**.

## Устройство (из плана, обязательное)

- **Статус — файл в каталоге заметки**, по действующему правилу `NotesStore` («статус — это
  наличие файлов, отдельного state-файла нет», `NotesStore.kt:7-8`). Отдельного state-механизма
  не изобретай. Воркер пишет файл перед терминальным состоянием и **удаляет при удаче**.
- **Файл статуса не уезжает в GitHub.** `PushWorker` собирает заметку только из `transcript.md`
  — это надо **закрыть тестом**, а не рассуждением: следующий агент поменяет сборку и не
  заметит.
- **Нет ключа → `Result.retry()`, а не `failure()`** (сегодня в `TranscribeWorker` уже `retry`,
  сохрани это): запись обязана остаться в очереди.
- **«После ввода уходит сама» — встроенным механизмом:** после сохранения ключа `MainActivity`
  ставит в очередь локальные записи без `transcript.md`; `ExistingWorkPolicy.KEEP`
  (`PipelineQueue.kt:43`) сам пропустит те, что ещё в очереди. Нового механизма очереди не
  изобретать — WorkManager уже несёт очередь, повторы и constraint.
- **Запись `transcript.json` и `transcript.md` — через `.tmp` + `renameTo`**, как уже делают
  `RepoCache` и `WriteQueue`. Убитый процесс посреди записи оставляет обрезанный
  `transcript.md`, а он навсегда выключает перераспознавание (воркер при существующем
  `transcript.md` выходит `success`) и молча уезжает в GitHub.
- **Пустой ответ вендора не выдаём за расшифровку.** Сегодня `words: []` даёт пустой
  `transcript.md`, и заметка навсегда считается расшифрованной. Это родня обрезанному файлу —
  закрывается здесь же.
- **Фатальные коды: все 4xx, кроме 408 и 429** (они про «попробуй позже»). Сейчас в коде ровно
  `400/401/403`, из-за чего 404 и 422 уходят в бесконечные повторы по 48 МБ. Это **решение
  ведущего** по находке ревью среза 1, менять его не надо — надо выполнить.
- **Долг из среза 1:** онбординг и `setupComplete()` (`MainActivity.kt`) не покрыты ни одним
  тестом, тестов `MainActivity` в репо нет вовсе. Этот срез трогает `MainActivity` по существу,
  поэтому страж заводится здесь. Если честного дешёвого способа нет — **скажи это в отчёте**
  (правило 4), не подгоняй тест под задание.

## Слова на экране (выбрал ведущий, владельцу показаны отдельно)

Тон и регистр — как у соседних строк: строчная буква, без восклицаний, без «!». Комп v3 и
`DESIGN.md` — жёсткое ограничение: новых экранов, новых цветов и новых компонентов срез не
вводит.

## Примеры входа → выхода

1. Ключа ElevenLabs нет, владелец записал заметку → в ленте у записи «нет ключа ElevenLabs»;
   запись **в очереди**, не потеряна. Владелец вводит ключ в настройках → запись расшифровывается
   **сама**, без единого тапа по заметке.
2. Ключ с опечаткой → ElevenLabs отвечает 401 → в ленте «ошибка ElevenLabs 401», в деталке тот же
   текст плюс начало тела ответа; запись цела, тап по «Повторить» ставит её заново.
3. ElevenLabs ответил 404 или 422 → это тоже фатально: `failure` и текст в статусе, а не вечные
   повторы.
4. ElevenLabs ответил 429 или 503, либо оборвалась сеть → как раньше: тихий `retry`, статус не
   меняется на ошибку.
5. Расшифровка удалась → файла статуса нет, лента показывает заметку как расшифрованную.
6. Процесс убит посреди записи `transcript.md` → в каталоге не остаётся обрезанного
   `transcript.md`; заметка не считается расшифрованной и распознаётся снова.
7. Вендор вернул пустой список слов → заметка **не** помечается расшифрованной навсегда.

## Мутации (обязательные)

Формат TOML и правила — шапка `/home/nikitatrubaev/code/noteapp/scripts/mutate.py` и
`/home/nikitatrubaev/code/noteapp/docs/harness/epic.md` → _Мутационная проверка_.

1. снять запись файла статуса — убивает тест «без ключа виден текст»;
2. `failure` вместо `retry` на «нет ключа» — убивает тест «запись остаётся в очереди»;
3. не удалять статус при удаче — убивает тест «после удачи статуса нет»;
4. писать `transcript.md` напрямую вместо `.tmp` + `renameTo` — убивает тест обрыва записи;
5. вернуть фатальными только `400/401/403` — убивает тест 404 или 422.

**Управляющая обязана быть хирургической** — такой, которую видит ровно ОДИН тест во всём
наборе: `--scope full` гоняет её пустым фильтром по всему набору и требует ровно одного падения.
Управляющая, ломающая что-то центральное (формат тайм-кода, общий хелпер), этой проверки не
проходит по построению — на этом уже споткнулся срез 1.

Прогон: `scripts/mutate.py run --id nikitatrubaev-u4g.2 --spec <файл.toml> --scope full`, затем
`scripts/mutate.py table --id nikitatrubaev-u4g.2`. **rc обязан быть 0.** `tests` каждой мутации
сужай до одного теста.
