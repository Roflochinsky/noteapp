## 3. МУТАЦИЯ

Полный набор прогнал ведущий на сданном HEAD (исполнитель сделал только узкий, `full_run` был
пуст — дыра приёмки, закрыта ведущим). `scripts/mutate.py run --scope full` → **rc=0**: M1–M5
убиты, управляющая убита, полный прогон под управляющей — ровно одно падение.

Управляющую пришлось заменить: исходная (формат тайм-кода `[%02d:%02d]` → `[%d:%d]`) слишком
центральная, её видят шесть тестов, а правило требует ровно одного падения. Это не дыра в
стражах — все шесть настоящие тесты формата, стражи плотные и перекрываются. Хирургическая
управляющая — `ElevenLabsClient.FILENAME` `audio.m4a` → `audio.bin`, её видит ровно один тест
multipart.

Ось СПЕКА приложила текст трёх мутаций, которых в наборе не было и которые сейчас выживают
(`X1`–`X3`) — они ушли в круг фикса.

## Находки в сам харнесс (не в срез)

1. **Управляющая мутация обязана быть хирургической.** `--scope full` сверяет её пустым фильтром
   по всему набору и требует ровно одного падения — центральная управляющая не проходит по
   построению. В `docs/harness/epic.md` этого требования нет.
2. **`bin/gate` не печатает sha в файл вывода**, из-за чего правило «результат существует только
   вместе с хешем» держится на слове журнала.
3. **Две оси в одном дереве несовместимы с прогоном мутаций ревьюером**: ветка выкладывается
   только в одно дерево, а `mutate.py` временно подменяет исходники. Решение этого круга —
   мутации гоняет ведущий до диспатча осей; стоит записать правилом.
