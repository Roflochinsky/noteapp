## Твои пункты вердикта

1. **ГЕЙТЫ.** Принимаешь по sha из журнала (HEAD совпал, копия чистая, файл вывода есть, первая
   строка файла — sha). Сам не гоняешь.
2. **СПЕКА.** По строке на КАЖДЫЙ из критериев 5 и 6: `<спека>:<строка>` → тест по ИМЕНИ либо
   «нет теста, ловится <чем>». Тест, который прошёл бы и на неверной реализации, за покрытие не
   считается — скажи прямо.
3. **МУТАЦИЯ.** Суди таблицу: управляющая убита? хирургическая ли она (полный прогон дал ровно
   одно падение)? **каждая ли мутация разделяющая** — различает верную семантику и ближайшую
   неверную, а не ломает всё подряд? Выжившая мутация = `CHANGES REQUESTED` без обсуждения.
   Нужна мутация, которой в наборе нет, — назови её текстом (`file`, `find`, `replace`, `tests`,
   `expect_fail`), прогонит ведущий.
4. **ФОРМАТ/ПРИВАТНОСТЬ.** Срез трогает файл репо заметок, аудио или ключи? Главный вопрос:
   **файл причины не должен попадать в GitHub** — проверь сам, каким тестом это держится и что
   этот тест ВИДИТ. Исполнитель сам говорит, что тест стоит в `RawNoteTest` и не покрывает набор
   `Input` в `PushWorker.doWork` — оцени цену этой дыры.
5. **СКОУП-КРИП.** Изменённые файлы против «Трогает:». Исполнитель объявил один файл вне списка
