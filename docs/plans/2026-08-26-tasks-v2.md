## Модульная раскладка (LLD)

Новое живёт рядом с существующим пайплайном, чистые модули — отдельно от сети и Android:

```
pipeline/
  TaskFile.kt        (новый, чистый)  разбор/сборка файла задачи + подзадачи
  Registry.kt        (новый, чистый)  projects.md / people.md; переименование персоны
  DoneNoteParser.kt  (есть)           + project/tags, секция «Задачи» как ссылки
  RepoDelta.kt       (новый, чистый)  compare-ответ → действия над кэшем
  ConflictRule.kt    (новый, чистый)  решение по 409
  RepoCache.kt       (новый)          файлы кэша + карта путь→blobSha + lastCommitSha/ETag
  SyncEngine.kt      (новый)          оркестрация чтения/записи поверх GithubClient
  GithubClient.kt    (есть)           + trees/compare/blobs, update, delete, батч-коммит
ui/
  TaskFilter.kt      (новый, чистый)  фильтрация и сортировка списка задач
  TasksScreen.kt     (новый)          экран задач по компу
  TaskDetailScreen.kt(новый)          деталка задачи
  FeedScreen.kt      (есть)           + переключатель вкладок и чипы-фильтров
  DetailScreen.kt    (есть)           + поля-чипы, правка саммари, удаление
  FilterChips.kt     (новый)          чипы + шторки выбора (общие для ленты и задач)
  DeleteDialog.kt    (новый)          диалог удаления с галочками
```

Решения, принятые здесь (не переоткрывать в исполнении):

1. **Схема frontmatter — только в ADR**, в коде не дублируется прозой; `TaskFile` — её
   единственная реализация.
2. **Необязательные поля опускаются**, а не пишутся пустыми: нет проекта — нет строки
   `project`. Круговой прогон «разобрать → собрать» обязан давать тот же текст.
3. **Порядок сортировки задач**: приоритет (P1→P3), внутри — просроченные, затем со сроком по
   возрастанию, затем без срока по дате создания. Сделанные — вне списка, в свёрнутой секции.
4. **Кэш — файловый, рядом с `NotesStore`** (`files/repo/`), состояние синка — один
   json-файл; отдельной БД не заводим (ponytail: Room ради шести полей не нужен).
5. **Очередь записи — существующая, `PipelineQueue`/WorkManager**, расширяется типом операции
   (создать / обновить / удалить / батч). Однопоточно, ≥1 с между мутациями.
6. **Батч-коммит (git data API)** — один метод `GithubClient.commitBatch(changes)`; им идут
   удаление с задачами, переименование персоны, миграция. Одиночная правка — contents API.
7. **409 — `ConflictRule`**: сравнить поле, которое правил владелец, с тем, что в git;
   не менялось → переиграть молча, менялось → вернуть расхождение в UI.
8. **UI-состояние фильтров** — в `rememberSaveable` экрана, между запусками не переживает
   (ponytail: настройка не заслуживает хранилища, пока владелец не попросит).

## Срезы (LLD)

### С1 — формат: задачи и реестры разбираются и собираются

`TaskFile`, `Registry`, расширение `DoneNoteParser`. Фикстуры — реальные `.md` в
`app/src/test/resources/`. Тесты: круговой прогон, необязательные поля, подзадачи, старые
заметки без новых полей, переименование персоны в тексте.
**Демонстрация:** зелёный полный гейт + вывод `testDebugUnitTest` с именами тестов.

### С2 — Action v2: задачи из разговора становятся файлами

Правка `docs/examples/process-notes.yml`: промпт извлекает задачи в `tasks/`, ставит ссылки
вместо чекбоксов, сопоставляет имена с `people.md`, новых персон не заводит, `tasks/` и
done-заметки не трогает. Не пересекается с С1 по файлам — можно вести параллельно.
**Демонстрация:** `actionlint` зелёный + дифф промпта. Живой прогон на репо заметок — утром
владельцем (граница автономии).

### С3 — чтение репо: список задач приходит из GitHub

`RepoDelta`, `RepoCache`, `SyncEngine` (чтение), расширение `GithubClient` (trees, compare,
blobs, ETag). Холодный старт — trees + чтение файлов; обновление — ETag → compare →
дочитать изменённые. Экрана ещё нет: результат виден отладочным списком и тестами.
**Демонстрация:** гейты + тесты `RepoDelta` на записанных ответах API (фикстуры из research).

### С4 — экран задач: список, рубрики, фильтры

`TaskFilter`, `TasksScreen`, `FilterChips`, переключатель вкладок в шапке. По компу: рубрики
P1/P2/P3, янтарная просрочка, свёрнутое «Сделано», чипы со шторками, значения из реестров.
**Демонстрация:** гейты + тесты `TaskFilter` + APK; экран — на скриншоте эмулятора нельзя,
поэтому владельцу утром.

### С5 — правка и создание задачи

`TaskDetailScreen` (сегмент статуса, поля, подзадачи, ссылка на источник), создание шторкой,
запись одного файла через contents API, `ConflictRule` на 409, очередь при отсутствии сети.
**Демонстрация:** гейты + тесты `ConflictRule` + APK.

### С6 — лента заметок v2 и правка заметки

Чипы-фильтры ленты (тип/проект/персона/тег/дата), деталка заметки: поля-чипы, выбор персон из
реестра с предложениями Claude, правка текста саммари. Транскрипт не редактируется.
**Демонстрация:** гейты + APK.

### С7 — удаление и переименование персоны

`DeleteDialog` с галочками (по умолчанию только файл в репо), удаление задачи, батч-коммит
`commitBatch` для «заметка + её задачи» и для переименования персоны по всем файлам.
**Демонстрация:** гейты + тесты батч-сборки дерева + APK.

### С8 — миграция существующих заметок

Разовый прогон: чекбоксы «Задач» в done-заметках → файлы `tasks/` + ссылки, одним батч-
коммитом. Запускается из экрана настроек кнопкой, идемпотентен (повторный запуск ничего не
меняет), сухой прогон показывает, что будет сделано.
**Демонстрация:** гейты + тест идемпотентности на фикстурах; живой прогон — владельцем.

## Порядок и параллель

С1 и С2 — параллельно (разные слои, файлы не пересекаются, каждому свой worktree). Дальше
последовательно: С3 → С4 → С5 → С6 → С7 → С8. С3 блокирует С4–С8 (без чтения репо нечего
показывать), С5 блокирует С7 (батч поверх одиночной записи).
