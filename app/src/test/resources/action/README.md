# Эталонная пара: что оставляет после себя Action

Это контракт между слоями, а не пример. Файлы здесь — побайтовый вид того, что промпт
`docs/examples/process-notes.yml` пишет в репо заметок; по ним проверяется парсер
приложения (срезы Н1/Н3). Схема полей живёт в одном месте — ADR
`docs/adr/2026-08-26-tasks-as-files.md`; эти файлы её иллюстрируют, а не переопределяют.

**Правило: промпт меняется только вместе с этой фикстурой.** Правишь промпт в
`docs/examples/process-notes.yml` — тем же коммитом приводишь сюда новый вид файлов и
чинишь упавшие тесты парсера. Иначе четыре копии схемы (ADR, парсер, промпт, рабочая копия
workflow в репо заметок) разъедутся молча и вылезут в рантайме.

| Файл | Что фиксирует |
|---|---|
| `note-done-with-tasks.md` | Заметка после обработки: порядок ключей frontmatter, блоки саммари через пустую строку, секция «Задачи» — только ссылки `../tasks/…`, чекбоксов-дублей нет. Транскрипт остался как от телефона («Спикер N»), Action его не переписывает. Имя `Серёга` нет в `people.md` — осталось как услышано, в реестр не добавлено. |
| `note-done-no-tasks.md` | Обратная совместимость: задач в разговоре нет → секции «Задачи» нет, всё остальное как в v1. Проекта в `projects.md` нет → поле опущено, не пустое. |
| `task-podnyat-limit-retraev.md` | Задача со всеми полями: `source` указывает на **конечный** путь заметки (папка типа, не `inbox/`), подзадачи — плоские чекбоксы. |
| `task-kupit-kabel.md` | Задача-минимум: необязательные поля (`project`, `due`, `tags`) и секция «Подзадачи» опущены целиком, файл заканчивается на закрывающем `---`. |

Обе задачи — из одной заметки `встречи/2026-08-26-0914-limity-retraev.md`; ссылки в заметке
и `source` в задачах сходятся. Инвариант, на котором держится относительная ссылка: папки
типов — первого уровня, вложенных папок в репо заметок нет.

Чего здесь нет и почему: коллизия имён (`-2`, `-3`) — правило промпта, отдельного файла не
требует; поле `done` — его ставит приложение при закрытии задачи, Action создаёт только
`status: open`.
